## Fixed: repeated inspection-limit warnings

In 1.1.0, the additional file-identity association search could stop after two seconds or after reaching fixed folder counts. On a busy or slower PC, this could mark otherwise completed checks of different applications as limited. The warning could also persist in saved history after a later inspection.

Version 1.1.1 completes that configured shallow AppData search on the existing background worker, rather than making completeness depend on those cutoffs. It also inspects entries beyond the former per-folder limits. The scope remains two directory levels under the supported AppData roots; protected locations and links remain excluded.

**After updating, run “Find leftovers” again for an affected history entry.** A fresh inspection discards the obsolete search-timeout warning. Genuine read failures and unrelated inspection limitations remain visible. A previously saved report is not silently rewritten as a successful scan.

The warning did not mean that deleted files had returned. This update does not broaden cleanup permissions or weaken ownership, fingerprint, shared-data or system-path protections. The contents-validation limits used before deletion are unchanged.

## Compatibility and validation

Release highlights now include hidden language headings understood by the original 1.0.0 updater, as well as the newer summary format. The visible GitHub description remains English-only. The 1.1.0 release description has received the same text-only compatibility correction.

Regression checks exercise enumeration delayed beyond the old deadline, an association after more than 1,500 child folders and beyond the old executable cutoff, genuine access failures, stale-warning removal and a verbatim copy of the published 1.0.0 summary parser.

The installer and updater continue to use the project's existing signing key. Download the `.exe` to install manually; `.signature.json` and `.sha256` are verification files. Windows 10/11 x64 is required.
